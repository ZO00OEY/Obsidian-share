
## 1. 手动：安装Codex

1. 前往 [Codex 官网](https://openai.com/zh-Hans-CN/codex/)，下载并安装桌面应用。
2. 打开应用并登录账号。
3. 打开要处理的项目或笔记文件夹，新建聊天即可使用。

## 2. 交给 AI：配置命令行入口

这是下一步通过命令安装 Ponytail 的准备。把下面这段发给 Codex：

```text
请在 Windows 上配置 Codex CLI 和 Node.js，为安装 Ponytail 做准备，并由你完成验证。

1. 检查 Get-Command codex、codex --version 及实际可执行文件位置。已有可用安装时不要重复安装。
2. 若命令不可用，先核对官方最新 Windows 安装说明，再修复已有安装的用户 Path，或安装官方独立 CLI。路径须动态获取，不得写死用户名或默认使用 .codex/.sandbox-bin。
3. 修改用户 Path 时，只追加已确认存在的命令目录，保留原有条目及 Codex 配置、登录信息和会话。
4. 检查 node --version；若未安装 Node.js，安装官方 LTS，供 Ponytail hooks 使用。
5. 完成后，从最新系统和用户环境变量刷新 Path，在新的 PowerShell 子进程中执行 Get-Command codex、Get-Command node 及两条版本命令，报告实际路径、版本和是否可以继续安装 Ponytail。
请直接执行，不要让我手动验证。验证失败时说明具体原因；仅在确有必要时提醒重启 Codex，并在重启后继续验证。未经验证不得报告成功。
```

配置和验证均交给 AI 完成，确认通过后再继续下一步。

参考：[官方 Windows CLI 安装与路径说明](https://learn.chatgpt.com/docs/enterprise/windows-deployment)。

## 3. 交给 AI：安装 Ponytail 插件（用于约束代码）

第 2 步完成后，把下面这段发给 Codex：

```text
请在 Windows 上安装 Ponytail 的 Codex 完整插件版，并尽可能全程代我操作。先阅读作者最新说明：https://github.com/DietrichGebert/ponytail/blob/main/INSTALL.md

1. 检查 Codex、Node.js、市场和插件，已有可用安装不重复安装，保留其他插件、配置及登录会话。
2. 按作者说明安装；遇错先依据官方说明、CLI 帮助和错误提示自行修复，不猜测配置。Path 只追加已确认存在的目录。
3. 审查当前版本全部 hooks。需要人工授权时，打开可见窗口，简述脚本作用，按实际界面逐步引导：每次说明当前操作及预期结果，收到反馈再继续。确认待审查项全部属于 Ponytail 后，才引导批量信任；
4. 授权后由你验证信任记录、Node.js 调用和 hooks 的实际执行证据，不把安装成功等同于生效。
5. 必须重启时，先保存进度并引导操作；我告知完成后继续检查，不要求固定回复口令。
请直接执行，仅将必须亲自操作的步骤交给我。最终简报安装、启用、信任、加载和实际执行状态，明确标出未验证项。
```

安装与检查交给 AI 完成，需要手动确认 hooks 或重启时，再按 AI 提示操作。
## 4. 交给 AI：优化 Windows 执行环境

第 3 步完成后，把下面这段发给 Codex：

```text
当前任务是修复 Windows 上 Codex 执行 PowerShell 命令时的中文乱码、文件读写和路径处理问题。请直接检查并修复：

1. 运行 $PSVersionTable.PSVersion 和 (Get-Process -Id $PID).Path，确认 AI 实际使用的 shell。检测并复用已有 PowerShell 7；若缺少，核对微软官方说明后自动安装，动态获取路径，避免重复安装。
2. 按当前 Codex 支持的方式，将 AI 执行环境持久切换到 PowerShell 7。不要把 Windows 默认终端或 Codex 集成终端的切换当作 AI shell 已生效。若无法持久切换，后续明确指定已验证的 pwsh.exe，并说明限制。
3. 检查并持久化 UTF-8 输入、输出和管道编码。先确认 AI 进程是否加载 profile，再选择受支持的方式；保留现有配置，修改已有文件前备份，尽量限定在 Codex 作用域。
4. 用新的 AI 命令进程验证实际 shell 路径、版本和编码，验证时不得临时补设编码或手动加载 profile。在临时目录测试中文读写、含空格的中文路径及子进程管道，完成后清理。
能自动完成的由你执行，遇错自行排查。确需人工操作或重启时，先保存进度，再逐步引导。

最后简报修改内容、实际 shell 路径与版本、验证结果和未解决项。安装或配置写入成功不代表修复已生效。
```

检查、安装和验证交给 AI 完成，需要手动设置或重启时，再按 AI 提示操作。

详细原因及其他排查方法见 Windows 执行环境优化与乱码排查。

## 5. 交给 AI：排查并优化高频日志写盘问题

把下面这段发给 Codex：

```text
请检查刚才这些操作期间，Codex 是否存在 TRACE 等日志导致 SQLite 数据库异常高频写盘的问题；结合近期日志和短时采样判断，没有异常就不用改。

如果存在异常，先核对当前版本是否有有效的日志过滤设置，不能只设置 RUST_LOG=warn 就认定解决。如果设置无效，可检查实际日志表结构，考虑用 SQLite 的 BEFORE INSERT trigger 配合 RAISE(IGNORE)，拦截已确认造成刷屏的 TRACE/DEBUG 日志，保留 WARN/ERROR；不要直接套用固定表名或字段。

修改前做好一致性备份并记录撤销方法，不删除会话或状态数据库，不把数据库设为只读。触发器只是临时缓解方案，可能影响诊断、被升级覆盖，也不保证消除全部写盘；处理后比较日志新增速率及实际写入情况，确认正常使用不受影响，再报告结果。能自动完成的由你执行。
```

## 6. 建议：使用技巧

### 1. 开启记忆，建立项目说明与工作约定

在 Codex 设置中找到并开启记忆功能，用于积累后续协作中可复用的信息。开始处理一个项目时，也可以先发下面这句话，让 AI 将项目要点整理到 `AGENTS.md`，作为后续工作的参考：

```text
通读当前项目，将项目结构、常用命令和重要注意事项精简整理到 AGENTS.md，用中文，保留已有有效约定，避免重复。
```

还可以在个性化设置的自定义指令中保存长期工作约定；只适用于当前项目的约定则写入 `AGENTS.md`。例如：

```text
需要操作本地软件时，优先使用可用的 CLI（命令行）、MCP 或软件 API；这些方式无法完成时，再使用界面自动化进行点击和键盘操作。
```

### 2. 用队列安排任务，用引导及时纠偏

在 **设置 → 常规 → 后续消息行为（Follow-up behavior）** 中，将默认方式从“引导（Steer）”改为“队列（Queue）”。这决定 AI 工作过程中收到新消息时，如何处理它。

任务较多时，建议按步骤拆成几条清晰的消息加入队列，让 AI 完成当前工作后再依次处理，减少多项要求混在长篇消息里造成的遗漏，也避免反复改变当前任务。必要的背景和约束仍应提前说清楚，拆分本身不保证效果更好。

如果发现 AI 正在做的方向不对，应及时使用“引导”，将纠正信息送入当前任务；已经排队的消息，也可点击该消息旁的“引导”按钮立即送入当前任务，不必等队列。**后续工作用队列，当前纠偏用引导。**

参考：[官方队列与引导说明](https://learn.chatgpt.com/docs/prompting)。

### 3. 用 Obsidian 管理和阅读 Markdown 文件

推荐使用 [Obsidian](https://obsidian.md/) 阅读、编辑和整理 AI 生成的 `.md` 文件，并配合 [Kepano 的 Obsidian Skills](https://github.com/kepano/obsidian-skills) 处理 Markdown、双链和笔记库。把下面这段发给 Codex：

```text
请帮我安装 Obsidian 和 Kepano 的 Obsidian Skills，并配置、验证命令行交互。已有可用安装时不要重复安装，保留现有笔记库、插件和设置。

1. 阅读 https://github.com/kepano/obsidian-skills 的最新安装说明，使用 npx skills add kepano/obsidian-skills 等当前支持的方式，安装到 Codex 能识别的位置，并检查技能是否能被发现。需要重启或新建聊天才能加载时告诉我。
2. 检查 Obsidian 应用和安装器版本是否支持 CLI；需要时从官网安装或更新。检查“设置 → 常规 → 命令行界面”是否已启用并完成注册；有界面控制工具时可尝试代我操作，否则告诉我具体要打开哪个开关，完成后由你继续。不猜测配置字段强行修改。
3. Windows 下检查安装目录中的 Obsidian.com 和用户 Path，必要时修复入口并刷新执行环境。在 Obsidian 运行时执行 obsidian help，并对目标笔记库做一次只读查询，验证确实能与应用交互，不把 Skills 安装成功当作 CLI 已可用。

能自动完成的由你执行；需要我手动开启开关、确认系统权限或选择笔记库时再具体提示。最后简报 Skills 安装与加载、CLI 注册和实际交互的验证结果。
```

如果需要手动开启命令行：进入 **Obsidian 设置 → 常规 → 命令行界面**，开启并按提示完成注册，再让 AI 继续验证，安装 Skills 不会自动开启这个开关。

参考：[Obsidian 官方 CLI 说明](https://help.obsidian.md/cli)。相关技能介绍见 [Codex Skills 推荐](#/notes/9i6zs2rlfthb)。

### 4. 聊天分支与工作树怎么选

从某条消息创建聊天分支，就是沿着当时的对话另开一条聊天；下面两个选项决定新聊天在哪里改文件：

- **在此工作树中创建分支**：聊天分开，文件共用，双方修改会相互影响。
- **在新工作树中创建分支**：在独立目录修改另一份项目文件，改动互不影响。完成后不会自动合并，需要你明确让 AI 合并回日常目录。

**修改 Obsidian 插件时怎么选？** 平时按顺序改功能、想随时在 Obsidian 看效果，就在日常笔记库对应的聊天里选“在此工作树”。需要同时试两种方案、隔离实验时，再选“在新工作树”，新工作树的改动不会直接显示在日常文件中。

记住：**聊天分支是另开对话，工作树是选择共用文件还是分开文件。**

详细说明见 Codex 工作树与分支流程。参考：[官方工作树说明](https://learn.chatgpt.com/docs/environments/git-worktrees)。

## 7. 拓展：连接云端 VPS

每台服务器复制一份下面的模板，填好后连同下方提示词一起发给本地 Codex。简称可写“洛杉矶小鸡”“华为云香港”等；SSH 端口非 `22`、用户名非 `root` 时请另行注明。

```text
服务器简称：____
公网 IP 或域名：____
登录凭据（二选一）：
- 密钥登录：私钥本地路径 ____；公钥路径 ____（可选，批量连接时注明对应服务器）
- 密码登录：SSH 登录密码 ____（或连接时手动输入）
```

私钥只提供本地路径；公钥不能单独用于登录。密钥和密码登录都走 SSH 端口。

```text
请根据我提供的信息，参考官方说明和《Codex 如何连接云端VPS》手动教程，选择人工操作最少的方式，完成这些服务器的 Codex SSH 远程连接。未注明时按 SSH 端口 22、用户名 root 尝试。

1. 将公钥、私钥按“服务器简称＋公钥/私钥性质”命名，统一整理到我指定的本机目录；未指定则用 ~/.ssh/codex-vps/，保留原文件。
2. 通过本地终端登录各服务器，按需生成密钥、部署公钥并配置本机 ~/.ssh/config，使用整理后的密钥路径验证 SSH 登录，保留已有配置。
3. 检查远程服务器是否已安装并登录 Codex，缺少时先安装。未登录时，由你逐台执行 codex login --device-auth，标明服务器简称并提供授权链接和一次性验证码；我完成浏览器授权后，由你继续验证登录状态。若需要开启设备代码登录，告诉我具体操作。
4. 协助在 Codex“设置 → 连接 → SSH”中添加或启用服务器、选择远程工作目录；能代操作的直接完成，否则给我准确的填写信息。最后通过远程聊天执行 hostname、whoami、pwd，确认实际连接到对应服务器。

配置、登录触发和验证尽量由你完成，只将必要的密码输入、浏览器授权及界面确认交给我。最后简报各台服务器的连接结果、密钥路径和待办步骤，不输出私钥内容或保存密码。
```

通常只需你按提示输入必要的登录凭据、逐台完成 Codex 网页授权，以及确认无法由 AI 代操作的连接设置；不需要自己运行安装或登录命令。已有有效登录时无需重复授权。

参考：[官方 SSH 远程连接说明](https://learn.chatgpt.com/docs/remote-connections)、[设备代码登录说明](https://learn.chatgpt.com/docs/auth)。

## 8. 修复：工作空间依赖安装卡死

如果 Codex 的工作空间依赖安装卡住或反复失败，把下面这段发给 AI：

```text
Codex 的工作空间依赖安装卡住或反复失败，请帮我排查并修复。可能是依赖包已下载，但 Windows 自动解压 .tar.xz 卡住，导致目录不完整。请确认实际安装目录、缓存目录和依赖版本，找到缓存包或重新下载，完整解压到 Codex 期望的目录，并验证依赖是否可用。
```
